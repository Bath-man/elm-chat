# 当前架构

## 运行结构

| 目录 | 职责 |
| --- | --- |
| `apps/web/` | React/Vite 客户端；开发端口 3000，代理 `/api` 和 WebSocket 到 8080 |
| `apps/server/` | Node HTTP/WebSocket 服务；生产同源提供静态页面、房间 API 和加密消息中继 |
| `packages/shared/` | 房间、成员和消息协议类型 |
| `packages/crypto/` | AES-GCM、ECDH、ECDSA 等端到端加密实现 |

房间密钥材料留在客户端，房间秘密通过 URL fragment 分享，不发送给服务器。客户端使用签名的加密载荷传输文字、图片及互动；服务器检查准入和中继事件格式，不保存正文或密文历史。

## 状态存放位置

| 状态 | 存放位置 | 生命周期 |
| --- | --- | --- |
| 房间、邀请、准入身份、恢复凭证摘要 | 当前 Node 进程内存 | 进程退出即丢失 |
| 浏览器身份密钥、会话与恢复凭证 | 同源 localStorage | 用户清理网站数据前保留 |
| 聊天正文、完整图片、互动和待发状态 | IndexedDB，按房间与会话隔离 | 房间失效不清除；用户清理网站数据会丢失 |
| `.achat` 备份 | 用户导出的文件 | 由用户保存，服务器不接收 |

服务端 `server.ts` 串行处理每个房间的请求和 WebSocket 事件；`room.ts` 管理双人席位、一次性邀请、重连鉴权和成员状态；`storage.ts` 仅实现进程内存存储。没有数据库、元数据文件、跨实例选主或状态交接。

## 房间与连接

生产只支持一个接流量实例、一个 Node 进程。不同进程中的房间状态互不相通；发布须停旧并断开旧 WebSocket，再启动或切到唯一新实例。部署要求统一维护在[部署指南](cloudbase-deploy.md)。

房间在原进程内仍存在时，刷新、关页重开或短暂断网可凭浏览器恢复凭证重新进入原席位，不消耗新邀请。快速退避重试耗尽后，每 30 秒开启新一轮；网络恢复事件可立即重试。

重启、回收、缩零或重新部署后，旧房间查询返回 404；过期或销毁的房间拒绝加入。客户端确认失效后停止重连，提示重新建房。旧页面可进入本地记录模式查看、导入和导出；发送禁用，旧待发内容不转移到新房间。

`/healthz` 表示进程存活，`/readyz` 表示当前进程可处理请求。二者不保证旧房间存在。

## 历史与备份

`history.ts` 先读取最近约 100 条，向上分页读取更早消息；互动状态和待发上下文单独读取。消息列表只渲染视口附近内容，加载更早记录时补偿滚动位置，新消息仅在底部自动跟随。

`history-archive.ts` 导出当前会话完整历史，包括图片、相对消息归属和点赞状态。在本机使用 PBKDF2-SHA256（210,000 次）、随机 16 字节盐与 12 字节 IV，生成 AES-GCM-256 加密备份。导入在本机解密、校验、按消息 ID 合并；导入记录不进入待发队列，也不重放互动。

备份加密不加密 IndexedDB 本身，不恢复房间准入，也不提供跨设备身份恢复。设备、对方保存内容及网络元数据的保护边界见[安全政策](../SECURITY.md)。
